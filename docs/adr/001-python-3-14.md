# ADR-001: Target Python 3.14

- **Date:** 2026-07-25
- **Status:** Accepted

## Context

The development plan initially assumed Python 3.13, on the expectation that
Streamlit's compiled dependencies would lag newer Python releases. The
development machine's default `python3` is 3.15.0, the newest release; 3.13
and 3.14 are also installed.

A check of PyPI showed Streamlit 1.66.0 (`requires-python >=3.11`) and its
compiled dependencies — pyarrow 26.0.0, numpy 2.5.4, pandas 3.0.6 — all publish
wheels for CPython 3.13, 3.14, and 3.15.

## Decision

The project targets **Python 3.14**: `.python-version` is `3.14` and
`pyproject.toml` declares `requires-python = ">=3.14,<3.15"`.

- **Not 3.13** — the compatibility concern behind it didn't hold up, and 3.14 is
  supported for longer.
- **Not 3.15** — it is very new; libraries added in Milestones 2–4 (for example
  Pydantic and an HTTP client for Ollama) may not support it yet.

## Consequences

- Every command runs through `uv run`, which uses the project's 3.14
  environment rather than the system `python3`.
- The upper bound `<3.15` makes a future upgrade an explicit change: bump
  `.python-version` and `requires-python`, run `uv lock`, and run the tests.
- Revisit when Milestone 2–4 dependencies are chosen, or once 3.15 has had
  several bug-fix releases.
- CI uses the same version, because `astral-sh/setup-uv` reads
  `.python-version`.
